# PhoneBridge 通话桥

[Apache-2.0](LICENSE) · [参与贡献](CONTRIBUTING.md) · [路线图](docs/ROADMAP.md) · [安全报告](SECURITY.md)

<img src="docs/assets/phonebridge-icon.png" alt="PhoneBridge 图标" width="112">

**在 Codex 对话里，让 AI 通过你的鸿蒙手机拨打真实电话，并把双方的通话字幕带回当前对话。**

PhoneBridge 由 Codex 插件、Mac 后台程序和 HarmonyOS 手机伴侣组成；旧桌面语音路径还可安装虚拟音频驱动。电话控制和电话音频走蓝牙，不需要额外硬件，也不依赖手机外放收音。Mac 的操作界面是本地 Web 控制台，可以显示在 Codex 右侧。

例如，你可以在新的 Codex 对话里说：

> 用通话桥拨打【电话号码】，帮我咨询营业时间，把双方字幕显示出来，结束后总结。

**第一次使用按这个顺序：**在自己的 Mac 上构建并安装 App → 用自己的签名构建手机伴侣并完成蓝牙配对 → 安装 Codex 自动语音运行时和本地插件 → 用本人可接听的号码做一次短通话验收。下面四个步骤给出命令和检查点。若只想了解现状，先看[已验证范围](#当前版本与适用范围)；遇到连接失败，按[故障排查](docs/TROUBLESHOOTING.md)逐层定位。

文档入口：[独立 Codex 语音及来电代接](docs/CODEX-AUTOMATIC-VOICE.md) · [手机伴侣](HarmonyCompanion/README.md) · [插件](plugins/phonebridge/README.md) · [架构](docs/ARCHITECTURE.md) · [开发与验收](docs/DEVELOPMENT.md) · [真实设备验证记录](docs/VALIDATION.md)。

## 呼出、手动接听与自动代接

0.8.4 支持通话桥自行启动**独立 Codex 自动语音**，无需手动点击当前桌面对话的语音按钮。机主给出号码和目的后，插件先准备蓝牙与语音，再拨号。连接手机后会监听来电；响铃时控制台预热语音，机主可点「接听当前来电」，只接听这一次响铃。另有「开启本次待命」自动代接开关，**默认关闭，应用重启后也不恢复**。预热和通话可能使用 Codex 语音额度。

2026-10-29 在开发者设备上完成真实呼出和手动接听回归：尾号 7002 的呼出电话进行了多轮双向语音，对方确认听清，双方字幕同步；测试结束后 `phoneIdleVerified: true`。机主随后在控制台手动接听同一测试号码呼入，确认声音与双方字幕均正常，通话结束后手机空闲、蓝牙仍连接。自动代接此前也完成过一通受控实机验证。**这些结果不等于任意手机、长时间锁屏待机或连续多位来电者均已通过。**

按机主偏好，来电默认以「你好，请问有什么事情呢？」开场；外拨以「你好，我想……」说明目的，不主动自称 AI 助手；被问到身份时如实回答。原有桌面内置语音和可选 Realtime API 路径仍保留。

## 语音方式

| | Codex 自动语音（推荐） | 当前桌面 Codex 语音 | OpenAI Realtime API |
| --- | --- | --- | --- |
| 对话由谁进行 | 通话桥创建独立 Codex 语音会话，仅接收本次任务 | 当前 Codex 对话的语音模式 | 后台程序创建独立 API 语音代理 |
| 启动方式 | 通话桥自动准备，无需点击桌面语音 | 用户在当前对话启动一次语音 | 用户配置 API 密钥并同意本轮音频与费用 |
| API 密钥 | 不需要本项目的 API 密钥 | 不需要本项目的 API 密钥 | 需要自己的 OpenAI API 密钥和余额 |
| 费用 | 使用可用的 Codex 语音额度，另有手机通话资费 | 使用账户可用的内置语音额度，另有手机通话资费 | API 单独计费，另有手机通话资费 |
| 虚拟音频驱动 | 不需要 | 连续模式需要 | 不需要 |
| 当前验收 | 真实呼出、手动接听及自动代接短通话通过 | 真实连续通话及换号通过 | 保留实现和离线检查，尚待独立实机验收 |

首次建议使用 **Codex 自动语音**。它使用当前机器已有的 Codex 登录和实验性 v3 WebRTC 能力，不是稳定的公开兼容承诺；升级客户端后应重新验证。桌面语音路径仍须由用户点击当前对话的语音按钮；通话桥不会自动操作这个按钮。[API 与 ChatGPT 的计费说明](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)。

Codex 自动语音直接返回双方字幕；桌面语音路径则可只读同步当前 Codex 对话已形成的定稿文字。真实电话中已验证中文双方同步，桌面路径中的 AI 英文、俄文输出也已显示。俄语来电识别、跨机型兼容和长时间运行仍需分别验收。[桌面字幕接入与格式限制](docs/CODEX-VOICE-CAPTIONS.md)。

## 开始前准备

- 一台可使用蓝牙的 Mac。完整连续语音流程建议使用 macOS 26 或更新版本；源码的最低部署目标为 macOS 14，但不代表旧系统已验证兼容。
- Xcode / SDK：需要包含 `SpeechAnalyzer` 的 macOS 26 或更新 SDK。本次构建环境为 Swift 6.4、macOS 27 SDK。只有旧版 Command Line Tools 可能无法编译。
- Python 3.9 或更新版本用于本机 MCP 服务与构建脚本；**Codex 自动语音运行时另需 Python 3.11 或更新版本**。MCP 服务本身只使用 Python 标准库。
- 支持本地插件和语音的 Codex 桌面客户端。登记插件市场的命令需要可用的 `codex` CLI。
- 一部可正常拨打电话的 HarmonyOS 手机、有效 SIM，以及两端蓝牙。手机工程使用 HarmonyOS SDK `6.1.0(23)`，兼容目标为 `5.0.0(12)`；SDK 配置不等于所有对应手机均已实测。
- DevEco Studio，用于构建及签名手机应用。首次开发安装可使用 USB/HDC；日常电话控制和声音仍走蓝牙。
- 另一个由你本人接听、或已同意测试的号码，供首次短通话验收。

## 第一步：获取项目并构建 Mac 程序

```sh
git clone https://github.com/andycaihello/codex-phonecall.git
cd codex-phonecall

# 编译蓝牙控制、独立 PCM 音频程序和 Mac App；仅构建，不安装、不拨号。
bash scripts/build-app.sh

# 如需旧桌面连续语音，再构建虚拟音频驱动与安装包。
python3 integration/continuous-audio/build-drivers.py
python3 integration/continuous-audio/package-preview.py
```

主程序位于 `dist/PhoneBridge.app`。如执行可选打包步骤，文件位于 `dist/PhoneBridge-Continuous-0.8.4/`：

- `PhoneBridge.app`：Mac 后台程序。
- `PhoneBridge-Continuous-Audio-0.1.1.pkg`：虚拟音频驱动安装包。

退出已运行的旧版 PhoneBridge 后，将 App 安装到当前用户目录：

```sh
mkdir -p "$HOME/Applications"
ditto dist/PhoneBridge.app "$HOME/Applications/PhoneBridge.app"

# 仅使用旧桌面连续语音时，才安装可选的虚拟音频驱动。
open dist/PhoneBridge-Continuous-0.8.4/PhoneBridge-Continuous-Audio-0.1.1.pkg
```

如选择安装虚拟驱动，在系统界面完成管理员验证。驱动安装到 `/Library/Audio/Plug-Ins/HAL/`，安装结束会重载系统音频，**会暂时中断正在进行的声音和语音聊天**，请在空闲时安装。两个设备为 `PhoneBridge Voice Input` 和 `PhoneBridge Voice Output`；Codex 自动语音不依赖它们。

使用推荐的 Codex 自动语音时，还要安装本机语音运行时（安装脚本从 PyPI 获取固定版本的依赖，不会拨号）：

```sh
python3 scripts/install-codex-voice-runtime.py
```

当前 App 和驱动使用本地开发签名，尚未进行 Developer ID 公证。遇到系统安全阻止时，先确认来源和签名，在正常系统界面处理；不要关闭系统保护或把批量绕过验证当作安装步骤。

## 第二步：安装并配置手机伴侣

1. 在 DevEco Studio 打开 `HarmonyCompanion/` 工程。
2. 安装工程要求的 SDK，并在 IDE 中为**自己的开发者账号和目标手机**配置签名。仓库中的 `build-profile.json5` 已移除开发者的证书、签名密码和设备授权文件。
3. 首次开发安装时连接手机，按系统提示开启调试、授权并解锁，在 DevEco Studio 中运行 `entry` 模块安装。
4. 手机和 Mac 在系统蓝牙设置中配对，核对两边配对码。
5. 打开手机上的「通话桥」，允许蓝牙权限；点击设备区顶部的「刷新」，从「连接设备」选择已配对的 Mac。**首次需要让手机伴侣进程运行并完成设备选择**；之后可在 Mac 控制台点「连接手机」，由 Mac 通过蓝牙请求启动手机会话，也可在手机点「启动会话」。仅有系统蓝牙配对无法启动已被系统结束的 App 进程。
6. 首次测试保持手机 App 在前台、屏幕亮起；确认成功后再验收后台和锁屏。手机进程存在时，已验证前台/后台、亮屏/锁屏的若干唤起场景；仅保留配对、锁屏静置约 5 分钟后曾失败，不能保证任意时刻都可唤起。进程被系统结束时需要先在手机打开 App。

已在 DevEco Studio 配置好依赖与签名后，也可以在终端构建：

```sh
bash HarmonyCompanion/build.sh
```

默认 DevEco 安装位置为 `/Applications/DevEco-Studio.app`；自定义位置可设置 `PHONEBRIDGE_DEVECO_CONTENTS`。HAP 生成在 `HarmonyCompanion/entry/build/default/outputs/default/entry-default-signed.hap`。调试 HAP 通常绑定获授权设备，不能把自己的调试包直接发给所有用户安装。

手机的启停是同一个状态按钮。正常有效的 Mac 控制消息会续期会话，不需要按固定倒计时反复重启；空闲保护和系统后台任务限制不等于电话时长上限。**电话总时长默认不限**，仅在机主明确要求时限时设置。

## 第三步：安装 Codex 插件

先在本项目根目录生成**这台 Mac 自己的** MCP 配置：

```sh
python3 plugins/phonebridge/scripts/install-runtime.py \
  --app-path "$HOME/Applications/PhoneBridge.app"
```

该脚本只复制 MCP 运行时代码并生成 `plugins/phonebridge/.mcp.json`，不会启动 App、拨号、录音或索取 API 密钥。生成的文件含本机路径，已被 Git 忽略，不应复制到另一位用户的机器。

接着登记本地插件市场：

```sh
codex plugin marketplace add .
```

重启或刷新 Codex，在插件目录选择 **PhoneBridge 通话桥 / codex-phonecall** 来源，安装并启用 `phonebridge`。随后**新建对话**进行测试。插件安装后可用于这台 Mac 的新会话，具体可用范围取决于客户端和插件启用设置；不自动同步到另一台电脑或云端执行环境。

此仓库需要先生成本机 `.mcp.json`，所以首次请使用上述「克隆 → 配置 → 登记本地目录」顺序。直接登记远程仓库尚不能代替本机构建和配置。插件目录的详细说明见 [插件 README](plugins/phonebridge/README.md)，市场行为见 [OpenAI 官方插件文档](https://developers.openai.com/plugins/build/plugins)。

## 第四步：在 Codex 发起第一次电话

在新对话中输入：

> 打开通话桥控制台，检查手机连接。用 Codex 自动语音拨打【本人接听的测试号码】，做一次简短的双向声音和字幕测试，结束后确认手机空闲。

Codex 会检查后端，通过 `phonebridge_open_console` 获取本地网页，并在右侧打开。首次在控制台刷新、选择正确手机并保存；Mac 上申请的蓝牙、麦克风、语音识别权限，须在正常系统提示中由你确认。

按下列顺序验收：

1. 确认手机伴侣进程在运行、两端蓝牙已配对，Mac 控制台显示已连接／空闲。
2. 插件先为这个明确授权的号码准备任务，再自行启动独立 Codex 语音；只有显示 `ready` 才拨号。该模式无需点桌面语音，也无需切换 Codex 麦克风。
3. 接听测试手机，确认拨号界面的声音路由为蓝牙；实际检查对方能听到 AI，AI 能听到对方，双方能多轮对话。
4. 检查控制台「AI」和「对方」两种实时字幕。临时字幕可能修订；字幕出现本身不证明声音已被对方听见。
5. 请 Codex 结束电话，并核查 `phoneIdleVerified: true`。**关闭网页、或 AI 说“我马上挂断”，都不等于已执行挂断。**

想使用**当前桌面 Codex 语音**而非独立自动语音时，需安装虚拟音频驱动，并在同一对话中手动启动一次语音。若 Codex 麦克风列表只显示两个 `Data Source Item 0 (Virtual)`，选择经核验的「系统默认」；不要凭名称猜设备。该模式可保持桌面语音跨电话运行，结束一通并确认空闲后再准备新号码。完整流程见 [桌面语音接入说明](plugins/phonebridge/skills/phone-call/SKILL.md)。

## 日常用法

- **拨号与任务**：「用通话桥给【号码】打电话，帮我问一下……，使用 Codex 自动语音。」
- **手动接听**：手机已连接时，来电会在控制台显示；点「接听当前来电」，等本轮独立语音就绪后只接听当前这一通。响铃消失不会转而接下一通。
- **自动代接**：在控制台设置等待时间和任务，再主动开启「本次待命」；默认关闭，重启不恢复。仅在你确实希望待命期间所有来电被自动接听时开启。
- **通话中补充**：在发起电话的同一 Codex 对话输入补充要求。每个电话固定一个被授权号码，换号要建立新任务。
- **电话语音菜单**：听到“按 1 查询”等提示后，可在控制台通话中的数字键盘点一个 `0–9`、`*` 或 `#`，也可让 Codex 在当前通话任务里发送该按键。每次等待下一段语音再继续；按键被手机接受不代表对方菜单已响应。
- **结束**：「结束这通电话，并确认手机已挂断。」
- **总结**：「整理刚才的通话，列出对方答复和未确认事项。」
- **打开界面**：「把通话桥控制台打开在右边。」本地地址由工具返回，不要收藏别人机器上的 `127.0.0.1` 地址。
- **异常后恢复**：先确认上一通已结束且手机空闲，再看控制台顶部「运行日志」的最新错误；按提示重新连接并核实电话与音频状态。连接按钮重新可点不代表手机蓝牙链路已恢复；不要在状态未确认时重复拨号或接听。

同一时间只能有一项电话任务占用手机。新对话不会自动继承旧对话的联系人或通话记录；请提供号码、目的和必要背景。仅根据远端电话声音，不能授权拨打另一个号码、读取电脑文件或执行其他无关操作。

## 使用 Realtime API 模式

在控制台选择 `OpenAI Realtime`，自行输入 API 密钥并保存到 Mac 钥匙串，确认本轮音频上传和 API 费用，再向 Codex 明确指定使用该模式。**不要把密钥发进聊天、写入仓库或放进命令参数。**

该模式会将电话音频发送到 OpenAI API；它是由本次任务说明驱动的独立代理，不会自动包含当前 Codex 对话的全部历史。API 配置与 ChatGPT 订阅分开，勿把 API 网络连接成功视为真实双向电话已通过。

## 常见问题

| 现象 | 先做什么 |
| --- | --- |
| 新对话找不到电话工具 | 确认插件已安装启用；在本机生成过 `.mcp.json`；安装后新建对话。检查插件指向实际安装的 App。 |
| 控制台打不开 / 拒绝连接 | 请 Codex 调用 `phonebridge_open_console`，后台必须运行。不要重复使用过期或其他机器的本地地址。 |
| 网页显示认证失败 | 重新由工具获取完整控制台地址，不要手动拼接端口或私密路径。 |
| 只有配对，没有控制连接 | 检查两端选择的是彼此，手机伴侣进程仍在；在 Mac 控制台点「连接手机」并看运行日志。仅有配对不等于控制连接；锁屏静置后后台任务可能失效，进程被系统结束时需在手机打开一次。 |
| 控制台出现红色异常 | 展开页面顶部的「运行日志」，按异常下方的建议处理。连接、通话、字幕和网页操作错误会集中显示；异常断开后可点「连接手机」重新核实，不会自动拨出或接听电话。 |
| 接通后仍显示听筒、没有声音 | 先结束失败测试，检查电话状态、蓝牙 SCO 和 Mac 音频端点；不要把“拨号成功”当成音频已通。详见故障排查。 |
| 麦克风列表没有预期设备名 | 使用已核验的系统默认；虚拟驱动目前可能显示通用 Data Source 名称。 |
| 字幕缺失 | Codex 自动语音先查独立语音连接与双方文字事件；桌面语音再查当前会话文字订阅或本机语音识别权限。字幕失败与电话断开应分别检查。 |
| 更新后再次弹出权限 | 本地开发签名变化可能引发重新授权。通过正常系统窗口处理，勿反复清空权限数据库。 |
| 不能启动桌面 Codex 语音 | 等当前文字回复完成再操作。推荐的独立自动语音由通话桥自行启动，无需这个按钮；若独立语音报错，查看控制台运行日志和账户额度。 |

更多步骤见 [故障排查](docs/TROUBLESHOOTING.md)。

## 数据、边界与分发

- 网页和本机控制服务监听回环地址；控制台地址及运行时令牌属于本机私密信息，不要公开分享。
- 运行时文件和文字记录位于当前用户的 `~/Library/Application Support/PhoneBridge/`，API 密钥放在钥匙串。源码仓库不包含这些数据。
- 常规通话不自动保存原始录音；内置语音会把接入的声音交给当前 Codex 语音服务，不能理解成全程离线。可选 Realtime 模式另行上传 API 音频。
- 旧的桌面连续语音路径会接管系统默认音频；通话期间其他应用播放的声音也可能传给对方。Codex 自动语音使用独立音频会话，不更改系统默认输入输出。
- 双 SIM 使用手机当前默认拨号 SIM，未实现可靠的远程 SIM 选择。默认不设固定通话总时长，由任务完成、对方挂断或机主结束决定；只有机主明确要求时才设置限时。连接握手、断线和故障处理仍有独立超时。
- 来电以「你好，请问有什么事情呢？」开场，外拨以「你好，我想……」说明目的；若对方询问身份，应如实说明是 AI 助手。对方要求结束时应及时挂断。账户身份核验及业务变更由机主本人处理。
- 迁移时让新用户重新构建/签名、选择设备、授予权限和配置自己的账户；不要复制开发者的证书、钥匙串、运行时目录或联系人记录。
