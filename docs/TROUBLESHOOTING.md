# 故障排查

按「安装与身份 → 控制连接 → 电话状态 → 真实音频 → 字幕」逐层检查。USB 调试在线仅表示可安装和诊断，不证明蓝牙电话通路正常。

## 插件没有出现或找不到工具

1. 在仓库根目录运行 README 的 `install-runtime.py`，确认 App 路径指向实际安装的位置。
2. 确认 `.agents/plugins/marketplace.json` 的来源指向 `./plugins/phonebridge`，并已通过 Codex 登记这个本地仓库。
3. 在插件目录安装并启用 `phonebridge`，重启/刷新后新建对话；旧的长会话可能没有新安装工具。
4. 确认使用本地 Mac 执行环境。另一台 Mac 或云端环境不能直接访问这里的回环服务。
5. 更新插件源码后需要刷新已安装副本。不要只改源码，就推断缓存里运行的版本已更新。

不要把开发者生成的 `.mcp.json` 复制到新用户机器，它含该机器的路径。

## 控制台打不开

让 Codex 重新调用 `phonebridge_open_console`，用返回的完整 URL 在右侧打开。后台退出时本地网页无法使用；`ERR_CONNECTION_REFUSED` 应先查后台是否启动。认证失败时重新获取 URL，不手动拼接私密路径，也不把地址分享给别人。

若系统阻止 App 启动，检查 App 身份及本地签名。不要通过清空钥匙串、权限数据库、所有配对记录等大范围操作来尝试修复。

## 手机已配对，但连接不上

1. 确认 Mac 和手机都保留彼此的同一条配对记录；更换手机后重新选择，不根据相似设备名猜测。
2. 确认手机伴侣进程仍在、蓝牙权限有效，手机已选择这台 Mac。进程还在且待命服务有效时，Mac 控制台可请求启动会话；进程已被系统结束时，先在手机打开一次 App。
3. Mac 控制台刷新并选择对应手机，保存后点「连接手机」；查看运行日志中的失败阶段及下一步建议。
4. 首次复现保持 App 在前台；确认没有其他电话或设备抢占。
5. 已发现蓝牙设备、辅助控制握手和电话音频就绪是不同状态，要分别核查。

正常消息会续期手机会话，当前应用层空闲租约为八小时；这不是系统后台任务的存活保证，也不是通话总时长。已验证前台、后台与刚锁屏时从 Mac 唤起；仅保留配对并锁屏静置约五分钟后曾出现后台任务停止、状态请求超时。若重连失败，先看红色运行日志和手机后台状态；不要反复拨号或把 USB 调试在线误判成蓝牙已恢复。恢复的判据是手机返回**新的**状态、会话已启动、电话空闲且 Mac 的蓝牙控制与音频端点就绪。[实机用例与结果](CONNECTION-RECOVERY-TEST-PLAN.md)。

若日志为 `RFCOMM_open_callback_without_channel`，表示 Mac 找到了手机的服务记录，但打开时没有得到可用通道；这不能单独证明手机当前仍在监听。若随后出现 `fresh-acl-not-verified`，Mac 连基础蓝牙链路也未重新建立。先确认手机在附近、蓝牙已开启，并查看伴侣 App 的待命或会话状态，然后由 Mac 控制台发起连接。手机系统蓝牙列表里直接点击 Mac 并非本项目的标准连接流程；不要把缓存的服务记录或「已配对」当作实时连接证明。

## 接通后显示本机听筒，或电话没有声音

先记录本轮状态并结束失败测试，不连续重拨陌生人。

- 检查电话是否真的接听，而不是仅处于呼出状态。
- 检查手机通话输出是否为蓝牙。Mac 可以拨号，不代表手机已把声音交给 Mac。
- 检查目标手机的两个蓝牙音频端点、PCM 是否已准备、SCO 是否实际保持，以及连续语音是否已切到电话通路。
- 若使用**旧桌面连续语音**，核对默认设备仍为两个虚拟端点。选择手机直连麦克风可能重走此前不稳定的设备切换流程；推荐的独立 Codex 自动语音不依赖这两个端点。
- 若出现路由错误或清理未确认，先检查当前电话是否空闲；旧桌面语音路径应在整个 Codex 语音结束后再恢复系统音频。不要把仍在运行的语音虚假标记为已停止来绕过检查。

若真人说听不到我方声音，分别核对 Codex `outputPCMBytes`、本机 PCM 的 `outputFramesWrittenToHAL8000` / `outputNonSilentFramesWrittenToHAL8000`、手机当前蓝牙通话路由，以及真人实际听感。字幕和 `outputPCMBytes` 只说明语音服务产生了内容；HAL 计数只说明非静音样本写入 Mac 音频回调，仍不能证明声音越过蓝牙和蜂窝网络。比较同一手机的成功通话与故障通话，尤其留意转人工、按键或路由切换后的变化；不要仅凭某一层计数认定对端听到。

Codex 自动语音的输出会每累计 120 秒 PCM 音频结束一个本机片段并开启下一个，避免手机通话尚在继续时触发音频程序的单片段 300 秒上限。此分段不会挂断电话；如仍出现 `Output duration or ten-second queue bound exceeded`，先核对当前通话与本机队列状态，再排查是否是十秒播放队列拥塞。

## 麦克风列表只有通用虚拟名称

目前驱动的 Data Source 名称可能显示为 `Data Source Item 0 (Virtual)`。不要任选一个；使用「系统默认」，再让插件核查：

- 输入 UID：`cn.andy.phonebridge.audio.input.device`
- 输出 UID：`cn.andy.phonebridge.audio.output.device`

驱动安装会重载系统音频，应安排在没有电话和语音运行时。已安装的驱动不要为了每次电话反复重装或重载。

## 无字幕、字幕重复或权限反复申请

Codex 自动语音先检查独立语音连接、双方音频帧与文字事件。旧桌面语音路径再确认当前会话文字订阅或本机麦克风与语音识别权限；macOS 26+ 才会使用新的双路本机识别后端。模型未安装时会显示未准备好，不能自动假定网络转写可替代。

识别文本会修订，当前仍可能出现临时/最终段落重复。字幕错误本身不等于音频失败；真人听感、音频状态和字幕分别验收。

开发版本重新本地签名可能导致 macOS 再次要求授权。通过系统窗口允许，并检查运行的是哪一份 App，不要反复清空 TCC 或关闭系统保护。稳定 Developer ID 签名是正式分发时待完成的工作。

## 想启动语音但没有按钮

这仅影响旧的当前桌面语音路径：Codex 正在处理文字任务时，语音启动控件可能不可见。让当前文字回复完成，再在同一会话启动语音。推荐的 Codex 自动语音路径会建立独立会话，无需点击桌面按钮；若启动失败，检查运行时安装、Codex 登录和语音服务状态。

首次启动成功后，连续模式不需要每通电话都停止和重启语音。说「挂断」后要实际执行结束工具，检查手机空闲；语音播出“已挂断”不代表工具已经执行。

## 向维护者反馈

提供系统版本、App/插件/手机版本、可复现的一步操作、失败阶段和已脱敏的错误。不要提交 API 密钥、运行时 URL/令牌、手机号码、蓝牙地址、通话全文、签名文件或未审查的截图。
