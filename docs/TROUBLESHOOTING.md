# 故障排查

按「安装与身份 → 控制连接 → 电话状态 → 真实音频 → 字幕」逐层检查。USB 调试在线仅表示可安装和诊断，不证明蓝牙电话通路正常。

## 插件没有出现或找不到工具

1. 在仓库根目录运行 README 的 `install-runtime.py`，确认 App 路径指向实际安装的位置。
2. 确认 `.agents/plugins/marketplace.json` 的来源指向 `./plugins/phonebridge`，并已通过 Codex 登记这个本地仓库。
3. 在插件目录安装并启用 `phonebridge`，重启/刷新后新建对话；旧的长会话可能没有新安装工具。
4. 确认使用本地 Mac 执行环境。另一台 Mac 或云端环境不能直接访问这里的回环服务。
5. 更新插件源码后需要刷新已安装副本。不要只改源码，就推断缓存里运行的版本已更新。

不要把开发者生成的 `.mcp.json` 复制到新用户机器，它含该机器的路径。

## 控制台打不开

让 Codex 重新调用 `phonebridge_open_console`，用返回的完整 URL 在右侧打开。后台退出时本地网页无法使用；`ERR_CONNECTION_REFUSED` 应先查后台是否启动。认证失败时重新获取 URL，不手动拼接私密路径，也不把地址分享给别人。

若系统阻止 App 启动，检查 App 身份及本地签名。不要通过清空钥匙串、权限数据库、所有配对记录等大范围操作来尝试修复。

## 手机已配对，但连接不上

1. 确认 Mac 和手机都保留彼此的同一条配对记录；更换手机后重新选择，不根据相似设备名猜测。
2. 手机打开通话桥，允许蓝牙，刷新并选择正确 Mac，启动会话。
3. Mac 控制台刷新并选择对应手机，保存后连接。
4. 首次复现保持 App 在前台；确认没有其他电话或设备抢占。
5. 已发现蓝牙设备、辅助控制握手和电话音频就绪是不同状态，要分别核查。

正常消息会续期手机会话。十五分钟失联保护不是过去的六分钟固定倒计时，不要把定期重启手机 App 作为正常使用流程。

## 接通后显示本机听筒，或电话没有声音

先记录本轮状态并结束失败测试，不连续重拨陌生人。

- 检查电话是否真的接听，而不是仅处于呼出状态。
- 检查手机通话输出是否为蓝牙。Mac 可以拨号，不代表手机已把声音交给 Mac。
- 检查目标手机的两个蓝牙音频端点、PCM 是否已准备、SCO 是否实际保持，以及连续语音是否已切到电话通路。
- 核对默认设备仍为两个虚拟端点。选择手机直连麦克风可能重走此前不稳定的设备切换流程。
- 若出现路由错误或清理未确认，先检查当前电话是否空闲；在整体 Codex 语音结束后再恢复系统音频。不要把仍在运行的语音虚假标记为已停止来绕过检查。

## 麦克风列表只有通用虚拟名称

目前驱动的 Data Source 名称可能显示为 `Data Source Item 0 (Virtual)`。不要任选一个；使用「系统默认」，再让插件核查：

- 输入 UID：`cn.andy.phonebridge.audio.input.device`
- 输出 UID：`cn.andy.phonebridge.audio.output.device`

驱动安装会重载系统音频，应安排在没有电话和语音运行时。已安装的驱动不要为了每次电话反复重装或重载。

## 无字幕、字幕重复或权限反复申请

确认麦克风与语音识别权限、本机中文语音模型、两个角色是否分别有音频帧。macOS 26+ 才会使用新的双路识别后端。模型未安装时会显示未准备好，不能自动假定网络转写可替代。

识别文本会修订，当前仍可能出现临时/最终段落重复。字幕错误本身不等于音频失败；真人听感、音频状态和字幕分别验收。

开发版本重新本地签名可能导致 macOS 再次要求授权。通过系统窗口允许，并检查运行的是哪一份 App，不要反复清空 TCC 或关闭系统保护。稳定 Developer ID 签名是正式分发时待完成的工作。

## 想启动语音但没有按钮

Codex 正在处理文字任务时，语音启动控件可能不可见。让当前文字回复完成，再在同一会话启动语音。插件不应一边等待你启动，一边持续占用文字任务。

首次启动成功后，连续模式不需要每通电话都停止和重启语音。说「挂断」后要实际执行结束工具，检查手机空闲；语音播出“已挂断”不代表工具已经执行。

## 向维护者反馈

提供系统版本、App/插件/手机版本、可复现的一步操作、失败阶段和已脱敏的错误。不要提交 API 密钥、运行时 URL/令牌、手机号码、蓝牙地址、通话全文、签名文件或未审查的截图。
