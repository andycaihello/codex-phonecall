# Codex 自动语音与来电代接（0.8.3）

这一模式由通话桥自行创建 Codex 的实验性 v3 WebRTC 语音连接。无需点击桌面语音按钮，也不需要将 Codex 的麦克风切换到手机。电话仍通过已配对手机的蓝牙 HFP 拨号、接听及挂断，声音复用通话桥的双向 PCM 引擎。

它是**独立语音会话**，只接收本次机主交给插件的任务，不会自动复制整个桌面聊天记录。双方字幕直接从该语音连接返回控制台和插件 `read_call`。

## 安装与使用

1. 保留现有手机伴侣及蓝牙配对，先完成主 README 的手机和 Mac 安装步骤。
2. 安装可选的 WebRTC 运行时（需要 Python 3.11 或以上版本）：

   ```sh
   python3 scripts/install-codex-voice-runtime.py
   ```

   依赖安装在当前用户的 `~/Library/Application Support/PhoneBridge/codex-voice-runtime`，不改变系统 Python。安装脚本固定 aiortc 和 PyAV 版本，从 PyPI 安装二进制包；运行时不会自动下载依赖或更新软件。

3. 在同一 Mac 的官方 Codex 客户端或 CLI 中完成 ChatGPT 登录。可以用 `codex login status` 检查。无需输入 OpenAI API key，程序也不读取或导出登录凭据文件，由官方 CLI 自行处理认证。
4. 构建并运行 Mac App，在本地控制台选择“Codex 自动语音 · 实验”，保存设置。
5. 可以先点“检查自动语音（不拨号）”：它自行启动语音，要求服务返回一段静音隔离的自检回复，确认实际音频和定稿文字均收到后关闭连接。不连接电话，不采集麦克风。
6. 首次使用请点“允许通话音频”，在系统窗口允许实际的 `PhoneBridge PCM Audio` 音频助手；检查与授权均不录音。拨号前会核实这个助手的权限，缺少权限时不拨号或接听。仅检查主程序的权限不足以证明音频助手已获授权。外拨时填写号码与任务，点“启动自动语音”；实际语音就绪后才能拨号。插件对应流程为 `prepare_call(mode: codex_voice)` → `prepare_codex_voice` → 等待 `ready` → `start_call`。每个任务仍固定一个授权号码，不跨任务重拨。
7. 手机蓝牙控制连接在线后持续监听来电。控制台检测到响铃时会预热独立 Codex 语音；这个过程可能使用语音额度，但不会自行接听。机主点击“接听当前来电”后，程序仅对该响铃实例发送接听指令；如果语音仍在启动，页面显示请求已排队。来电消失或替换则取消，不接下一通。插件手动代接仍可使用 `prepare_incoming(mode: codex_voice)` → `prepare_codex_voice` → 等待 `ready` → 机主要求后 `answer_call`。无需桌面语音启动或人工“语音已启动”确认。

与桌面内置语音路径不同，这一模式不使用 PhoneBridge 虚拟音频接口、不改变系统默认输入输出、不需要停止桌面语音后再恢复设备。它不会自动打开或控制当前桌面聊天中的语音按钮。

## 自动接听设置

控制台“Codex 自动语音”面板下有“来电自动代接”：

- **响铃后等待**：0 至 30 秒；0 为就绪后立即接听。
- **代接任务**：例如“说明自己是我的 AI 助手，记录对方来电目的并转达，不替我作承诺”。只传入这里的明确任务。
- **本次待命开关**：由机主在控制台主动开启，明确允许本次待命期间自动接听所有来电，并将通话音频发送至 OpenAI、使用 Codex 语音额度。

自动接听默认关闭；应用重启后也始终关闭。可以保存等待时间和任务偏好，不能通过恢复配置自动恢复接听授权。关闭开关不打断当前已经接起的电话，但不会再接新电话；空闲的待命连接会停止。

程序先预热语音并验证回复，再开始等待来电。来电振铃标识改变时重置等待过程；在发送接听指令之前，原生 HFP 控制器还会重新核对选定的振铃实例。语音失败、蓝牙失联、电话状态不明确或上一通未验证空闲时，不接下一通；故障会退出自动待命，不进行无人值守重拨。

一通电话正常结束并确认手机空闲后，关闭这一通的独立语音连接，再为下一位来电者创建全新连接。上一位的字幕、语音上下文和控制租约不会继承给下一位。对方明确要求结束当前电话时，本地控制器可以直接处理挂断，不把对方的话当作授权任何新电话或电脑操作；AI 告别后的延迟结束仅作用于当前拥有的电话。

没有可验证的来电者身份，因此当前版本不提供按联系人或白名单接听，也不支持呼叫等待、多路通话或人工转接。

## 验证记录与限制

2026-10-29 已完成：

- 本机官方 CLI `0.165.0-alpha.1.2` 的隔离实验：WebRTC + `version: v3`，现有 ChatGPT 登录，音频输入、语音输出和双方文字均返回，同一会话多轮成功。
- 新 JSONL/PCM 封装的真实语音服务联调：准备期间不向电话输出音频；合成输入被识别、收到语音回复并完成两轮对话；结束后实验进程退出。
- Mac App 内的“不拨号检查”：自行启动语音、收到实际音频与定稿文字、关闭连接并验证进程退出。
- 离线检查覆盖默认关闭、就绪前禁止拨号、关闭后不接新电话、响铃等待取消、启动失败不接听、两位来电者分别创建会话、历史记录不泄漏新租约等场景。原有外拨、手动接听状态机仍分别检查。

0.8.0 已完成真实外拨和自动接听各一通：均无需开启桌面语音，双方语音和字幕正常，电话结束后确认手机空闲。0.8.2 将语音准备提前到响铃时并增加接听排队反馈，真实手动接听测试出现双方字幕和正常声音。0.8.3 按机主偏好调整开场词，来电先询问来意，外拨先说明目的，被问身份时如实回答。

2026-10-29 的 0.8.3 回归中，尾号 7002 的真实呼出完成多轮双向对话，受话方确认声音清楚，双方字幕同步，结束结果为 `phoneIdleVerified: true`；随后机主在控制台手动接听该测试手机的来电，确认声音和双方字幕正常，通话结束后全局状态显示手机空闲、蓝牙仍连接、独立语音已清理。上述为同一套开发者设备的短时验证。长时间待命、系统结束手机进程、连接断开后恢复、多位来电者连续循环仍需分别测试。[蓝牙恢复测试计划](CONNECTION-RECOVERY-TEST-PLAN.md)还记录了仅保留配对并锁屏约五分钟后的唤起失败，不应把一次通话成功写成长期稳定性保证。

实验接口并非稳定的公开语音产品保证。默认 WebSocket 方式曾返回需要 API key 认证；默认版本的 WebRTC 曾出现协议标记不匹配。当前实现使用本机 CLI 生成协议明确支持的 v3 WebRTC 参数，不修改内部请求头、不冒充官方桌面客户端、不绕过账户权限。

现有 ChatGPT 登录成功不代表免费或无限额度；实际受账户计划、服务额度和实验能力开放范围限制。初始化及握手仍有超时；电话总时长默认不限，只有机主明确设置正数时限时才启用总时长限制。

旧的桌面内置语音和 Realtime API 路径保留原有流程。失败时先检查电话是否空闲，关闭自动代接，再处理后台；不要同时运行两个蓝牙控制器。音频助手源文件未改动时构建会复用同一份已签名程序，减少因无关主程序修改造成的重新授权；源文件、工具链或签名变化仍可能需要系统重新授权。
